## 1. Что делает программа (за 30 секунд)

1. Пользователь вводит название факультета и количество экзаменов.
2. Открывается меню. Все студенты хранятся в бинарном дереве `BinaryTree<Student>`, упорядоченном по Ф.И.О.

| `tree.h` | Условие, объявление шаблона `BinaryTree<T>`, в конце `#include "tree.tpp"` |

## 3. Теория

### 3.1 Что такое шаблон

Шаблон — это «чертёж» класса или функции, в котором тип данных заменён параметром.

```cpp
template <typename T>
class BinaryTree { ... };
```

`T` — параметр шаблона. При использовании `BinaryTree<Student>` компилятор подставляет `Student` вместо `T` и **генерирует настоящий класс**. Это называется **инстанцированием**.

Важные следствия:
- `BinaryTree<int>` и `BinaryTree<Student>` — два **разных, несвязанных** класса.
- Шаблон проверяется дважды: общий синтаксис при объявлении, а подставленный тип при инстанцировании. Поэтому ошибки вида «у `Student` нет оператора `<`» появляются только при использовании.
- Всё происходит на этапе **компиляции** (статический полиморфизм), в отличие от виртуальных функций (динамический, во время выполнения). Шаблоны не требуют общего базового класса и не имеют накладных расходов на vtable.

**Зачем шаблоны:** написать контейнер один раз и использовать для любого типа без дублирования кода и без потери типобезопасности (в отличие от `void*`).

### 3.2 Требования к типу `T`

Шаблон неявно требует, чтобы у типа были:
- конструктор копирования и `operator=` (данные копируются в узлы и при удалении узла);
- `operator<` (упорядочивание);
- `operator<<` для `std::ostream` (вывод).

Для `int` всё это есть встроенно. Для `Student` мы **добавили** `operator<` и `operator<<`.

**Почему только `<`, а не `==`:** два элемента считаются равными, если ни один не меньше другого: `!(a < b) && !(b < a)`. Это стандартный приём (так работает `std::set`, `std::map`).

### 3.3 Бинарное дерево поиска (BST)

Дерево, где у каждого узла не более двух потомков (левый и правый), и выполняется **свойство упорядоченности**:
- всё в левом поддереве меньше значения узла;
- всё в правом поддереве больше.

Благодаря этому поиск идёт как бинарный: на каждом шаге отбрасывается половина (в хорошем случае).

**Сложность** (h — высота дерева):
- поиск, вставка, удаление: **O(h)**;
- в среднем (случайный порядок вставки) h ≈ log n, то есть **O(log n)**;
- в худшем случае (вставка уже отсортированных данных) дерево вырождается в список, h = n, то есть **O(n)**.

Наше дерево **не самобалансирующееся** (не AVL и не красно-чёрное), поэтому вырождение возможно. Для лабораторной это нормально.

**Обходы:**
- симметричный (in-order): левое, узел, правое. Для BST выдаёт элементы **по возрастанию**. Используется в `printInOrder`;
- прямой (pre-order): узел, левое, правое;
- обратный (post-order): левое, правое, узел. Используется при удалении всего дерева (сначала потомки, потом сам узел).

Наш «боковой» вывод `printSideways` — это обратный симметричный обход (правое, узел, левое) с отступом по глубине. Поэтому правое поддерево оказывается сверху, а корень слева.

## 4. Разбор кода шаблона

### 4.1 Вложенная структура Node

```cpp
struct Node
{
    T data;
    Node* left;
    Node* right;
    Node(const T& value) : data(value), left(nullptr), right(nullptr) {}
};
```

- `Node` объявлена **внутри** класса в разделе `private`: это деталь реализации, снаружи она не видна.
- Конструктор копирует значение в `data` (поэтому нужен конструктор копирования у `T`).
- `nullptr` (C++11) вместо `NULL`: типобезопасный нулевой указатель.

Поля дерева: `Node* root` (корень) и `int count` (количество элементов).

### 4.2 Как устроено «открытое + закрытое»

Публичный интерфейс работает с значениями `T`, а рекурсия спрятана в приватных помощниках:

| Публичный метод | Приватный помощник |
|---|---|
| `add(value)` | `insertNode(node, value, added)` |
| `remove(value)` | `removeNode(node, value, removed)` |
| `find(value)` | `findNode(node, value)` |
| `print()` | `printInOrder`, `printSideways` |
| конструктор копирования, `operator=` | `copyNode` |
| деструктор, `operator=` | `clearNode` |

Причина: пользователю незачем знать про `Node` и передавать корень. Рекурсия же естественно записывается через узел.

### 4.3 Синтаксис, который могут спросить

**Определение метода вне класса:**
```cpp
template <typename T>
bool BinaryTree<T>::add(const T& value) { ... }
```
Перед каждым методом повторяется `template <typename T>`, а имя класса пишется с параметром: `BinaryTree<T>::`.

**`typename` перед `BinaryTree<T>::Node*`:**
```cpp
template <typename T>
typename BinaryTree<T>::Node* BinaryTree<T>::copyNode(const Node* node) const
```
`BinaryTree<T>::Node` зависит от параметра шаблона `T`, и компилятор на этом этапе не знает, `Node` — это тип или, скажем, статическое поле. Ключевое слово `typename` говорит: «это тип». Внутри самого класса (в объявлении) писать его не нужно.

**`bool& added` / `bool& removed`:** параметры-ссылки, через которые рекурсивная функция «сообщает наверх», удалось ли действие. Функция возвращает новый указатель на узел (корень поддерева), а флаг передаётся отдельно.

**`const T* find(...) const`:** возвращает указатель на найденный элемент внутри дерева (без копирования) или `nullptr`. `const T*` запрещает менять элемент снаружи, иначе можно было бы испортить порядок дерева (например, изменить Ф.И.О. и тем самым сломать упорядоченность). Второй `const` означает, что сам метод не меняет дерево.

### 4.4 Добавление (`add` → `insertNode`)

```cpp
if (node == nullptr) { added = true; return new Node(value); }
if (value < node->data)       node->left  = insertNode(node->left,  value, added);
else if (node->data < value)  node->right = insertNode(node->right, value, added);
return node;      // если ни меньше, ни больше: дубликат, ничего не делаем
```

Идея: спускаемся по дереву, как при поиске; дойдя до пустого места (`nullptr`), создаём там узел. На обратном пути рекурсии каждый узел перезаписывает свой указатель на потомка (чаще тем же значением), поэтому корень обновляется «сам». Дубликаты не добавляются, `add` возвращает `false`.

### 4.5 Поиск (`find` → `findNode`)

Спуск по дереву: меньше, идём влево; больше, вправо; иначе нашли. Дошли до `nullptr` — не нашли. Использует только `<`.

### 4.6 Удаление (`remove` → `removeNode`)

Сначала находим узел (тот же спуск). Затем три случая:

1. **Лист** (нет потомков) — удаляем узел, родитель получает `nullptr`. Попадает в ветку «нет левого потомка»: `child = node->right` (это `nullptr`).
2. **Один потомок** — узел удаляется, а на его место встаёт этот потомок (`delete node; return child;`).
3. **Два потомка** — нельзя просто убрать узел. Находим **минимум правого поддерева** (самый левый узел справа, преемник), копируем его данные в текущий узел (`node->data = minNode->data`), а затем рекурсивно удаляем этот минимальный узел из правого поддерева (у него нет левого потомка, поэтому он попадает в простой случай). Упорядоченность сохраняется: преемник больше всего слева и меньше всего справа.

Для копирования данных используется `operator=` типа `T`: для `Student` это наш `operator=` с глубоким копированием.

**Пример из тестового прогона.** Вставляли: Petrov, Ivanov, Sidorov, Antonov.

```
        Petrov                     после удаления Petrov
       /      \                   (два потомка: берём минимум справа)
   Ivanov    Sidorov                      Sidorov
     /                                    /
 Antonov                               Ivanov
                                         /
                                     Antonov
```

Минимум правого поддерева Petrov — это Sidorov (у него нет левого потомка). Данные Sidorov переносятся в корень, старый узел Sidorov удаляется.

### 4.7 Вывод (`print`)

Печатает два блока:
1. Структура дерева боком: правое, узел с отступом `4 * глубина` пробелов, левое. Корень слева, правая ветка сверху.
2. Отсортированный список (симметричный обход).

Для печати элемента используется `std::cout << node->data`, поэтому у `T` должен быть `operator<<`. Для `Student` выводится `Ф.И.О. (год, avg средний балл)`.

### 4.8 Управление памятью (правило трёх для шаблона)

Узлы создаются через `new`, значит нужны:

- **Деструктор** `~BinaryTree()` вызывает `clearNode(root)`: рекурсивно удаляет сначала левое, потом правое поддерево, потом сам узел (обратный обход). Если удалить узел раньше потомков, указатели на них будут потеряны (утечка).
- **Конструктор копирования** `BinaryTree(const BinaryTree&)`: `copyNode` рекурсивно создаёт новые узлы с копиями данных. Это **глубокая копия**: копия независима от оригинала. Поверхностная копия (`root = other.root`) привела бы к двойному удалению.
- **`operator=`**: проверка `this != &other`, затем `clearNode(root)` (освободить старое) и `copyNode` (скопировать новое).

В `main` пункт 5 демонстрирует конструктор копирования: `BinaryTree<Student> copy(tree);`.

### 4.9 Изменения в Student (по сравнению с лабой №3)

```cpp
bool operator<(const Student& other) const;           // сравнение по Ф.И.О.
std::ostream& operator<<(std::ostream&, const Student&);   // вывод одной строкой
```

- `operator<` сравнивает `fullName` (строки сравниваются лексикографически, по алфавиту). Это ключ дерева.
- `operator<<` — свободная функция (не метод), потому что левый операнд — `std::ostream`, а не `Student`. Возвращает ссылку на поток, чтобы можно было писать цепочки `std::cout << a << b`. Дружественной (`friend`) делать не нужно: она пользуется публичными геттерами.

Остальной `Student` остался прежним.

### 4.10 Как работает main

```
do {
    ввести факультет и число экзаменов (проверка exams >= 0)
    BinaryTree<Student> tree;
    do {
        показать меню
        switch (menu) {
            1: Student s(faculty, exams); s.input(); tree.add(s)
            2: создать «ключ» key, ввести Ф.И.О., tree.remove(key)
            3: tree.print()
            4: создать «ключ», tree.find(key) → вывести через print()
            5: BinaryTree<Student> copy(tree); copy.print()
            6: demoInt()  (BinaryTree<int>)
            0: выход из меню
        }
    } while (menu != 0);
    спросить Continue? (y/n)
} while (choice == 'y' || choice == 'Y');
```

**«Ключ» для поиска и удаления:** шаблон работает со значениями `T`, поэтому для поиска нужно подать ему объект типа `Student`. Создаём временный `Student` и задаём только Ф.И.О. (`setFullName`), остальные поля неважны, так как сравнение идёт только по Ф.И.О. После вызова найденный студент выводится целиком через `print()`.

**Защита от некорректного ввода:** если вместо числа в меню введены буквы, `cin` переходит в состояние ошибки; мы сбрасываем его (`clear`), очищаем буфер (`ignore`) и считаем выбор неверным, иначе программа зациклилась бы.

**Зацикливание программы:** внутренний цикл — меню (пока не выбран 0), внешний — повтор всей работы по запросу `y`.

**Освобождение памяти:** дерево — локальный объект, его деструктор вызывается автоматически при выходе из блока и удаляет все узлы. Каждый `Student` в дереве — копия (узел хранит значение `T`, а не указатель), поэтому временный `student` в `case 1` освобождается сам.

## 5. Возможные вопросы на защите

**1. Что такое шаблон класса? Зачем он нужен?**
Параметризованное описание класса, в котором тип данных передаётся параметром. Позволяет написать контейнер один раз и использовать с любыми типами без дублирования кода и потери типобезопасности.

**2. Что такое инстанцирование?**
Создание компилятором конкретного класса из шаблона при подстановке аргументов (`BinaryTree<Student>`). Для каждого набора аргументов получается отдельный класс.

**3. Почему определения методов шаблона находятся в заголовке (`.tpp`)?**
Компилятору нужен полный код при инстанцировании. Если определения лежат в обычном `.cpp`, для конкретного типа код не будет сгенерирован и линковщик выдаст ошибку неразрешённых символов.

**4. Чем шаблоны отличаются от виртуальных функций (полиморфизма)?**
Шаблоны: решение принимается на этапе компиляции, нет накладных расходов, не нужен общий базовый класс. Виртуальные функции: выбор во время выполнения через vtable, нужна иерархия наследования.

**5. Какие требования шаблон `BinaryTree<T>` предъявляет к `T`?**
Конструктор копирования, `operator=`, `operator<` (упорядочивание) и `operator<<` (вывод).

**6. Что такое бинарное дерево поиска? Какое у него свойство?**
Дерево с не более чем двумя потомками у узла, где левое поддерево содержит меньшие значения, а правое большие.

**7. Какая сложность операций?**
O(h), где h — высота. В среднем O(log n), в худшем (вырожденное дерево, например при вставке отсортированных данных) O(n).

**8. Как удалить узел с двумя потомками?**
Найти минимальный узел правого поддерева, скопировать его данные в удаляемый узел и удалить этот минимальный узел (он имеет не более одного потомка). Можно симметрично брать максимум левого поддерева.

**9. Почему вывод `in-order` отсортирован?**
Потому что сначала выводится всё левое (меньшее), потом узел, потом всё правое (большее), и так рекурсивно в каждом поддереве.

**10. Что такое глубокое копирование и где оно у вас?**
Создание для копии собственных узлов и собственных данных. У нас: `copyNode` для дерева и конструктор копирования `Student` для массива оценок.

**11. Что произойдёт без деструктора у дерева?**
Утечка памяти: все узлы, созданные через `new`, останутся не освобождены.

**12. Зачем `typename` перед `BinaryTree<T>::Node*`?**
`Node` зависит от параметра шаблона, компилятору нужно явно указать, что это тип.

**13. Почему `Node` объявлен внутри класса и `private`?**
Это деталь реализации. Пользователю дерева достаточно значений `T`; так можно менять устройство узла, не затрагивая внешний код.

**14. Почему `find` возвращает `const T*`, а не `T` или `bool`?**
Указатель позволяет получить сам найденный элемент без копирования и отличить «не найден» (`nullptr`). `const` не позволяет изменить ключ и сломать порядок дерева.

**15. Почему `operator<<` не метод класса?**
Левый операнд — `std::ostream`, а не наш класс. Метод класса вызывается у объекта слева от оператора, поэтому такую перегрузку делают свободной функцией (или `friend`).

**16. Почему равенство определено через `<`?**
`a` и `b` эквивалентны, если `!(a < b) && !(b < a)`. Это избавляет от требования `operator==` и согласуется с тем, как работают стандартные упорядоченные контейнеры.

**17. Что произойдёт при добавлении элемента с уже существующим Ф.И.О.?**
Дерево не изменится, `add` вернёт `false`, программа выведет сообщение об ошибке.

**18. Как работает поиск студента по Ф.И.О., если дерево хранит `Student`?**
Создаётся временный `Student` с нужным Ф.И.О. (ключ). Сравнение идёт только по Ф.И.О., остальные поля не важны.

**19. Почему рекурсивные функции возвращают `Node*`?**
Чтобы после вставки или удаления родитель мог обновить свой указатель на поддерево (например, при удалении узла на его место встаёт потомок; при вставке в пустое место создаётся новый узел).

**20. Минусы вашей реализации?**
Нет балансировки (возможно вырождение до O(n) и глубокой рекурсии), нет итераторов (обход только внутри `print`), оператор `<` и `<<` обязательны для типа. Для следующих этапов работы дерево можно разделить на классы итератора, контейнера и алгоритма.

**21. Чем `BinaryTree<int>` отличается от `BinaryTree<Student>`?**
Это два разных класса, сгенерированных из одного шаблона. Код методов одинаков, но типы данных в узлах и операции сравнения и вывода разные.

**22. Что такое `nullptr` и почему не `NULL`?**
Типобезопасный нулевой указатель C++11. `NULL` — это макрос, равный `0`/`0L`, и может вести к неоднозначности при перегрузке функций.

## 6. Быстрая шпаргалка

- `template <typename T> class BinaryTree` — чертёж; `BinaryTree<Student>` — настоящий класс (инстанцирование).
- Код шаблона должен быть виден в месте использования, поэтому `tree.h` подключает `tree.tpp`.
- Тип `T` должен иметь: копирование, `operator=`, `operator<`, `operator<<`.
- BST: левое меньше, правое больше. Поиск, вставка, удаление: O(h) (O(log n) в среднем, O(n) в худшем).
- Удаление: лист или один потомок — заменить потомком; два потомка — перенести минимум правого поддерева.
- Вывод in-order отсортирован. «Боком» — обратный in-order с отступами.
- Узлы через `new` → деструктор + глубокий конструктор копирования + `operator=`.
- Меню в цикле, внешний цикл `Continue? (y/n)`.
