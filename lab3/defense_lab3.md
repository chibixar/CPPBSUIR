# Лабораторная №3. Наследование. Подготовка к защите

Вариант 5: класс `Fakultet` порождает класс `Student`.

---

## 1. Что делает программа (за 30 секунд)

1. Пользователь вводит название факультета, количество студентов и количество экзаменов в сессии.
2. Для каждого студента создаётся объект `Student`, пользователь вводит Ф.И.О., год рождения и оценки.
3. Программа выводит всех студентов: факультет, Ф.И.О., год рождения, оценки, средний балл.
4. Затем создаётся **копия** первого студента (проверка конструктора копирования) и выводится на экран.
5. Вся память освобождается. Программа спрашивает `Continue? (y/n)` и повторяется (зацикливание).

### Стиль кода

- Имена методов и полей в `snake_case` (`get_full_name`, `exams_count`).
- К членам класса обращаемся через `this->`.
- Над каждой функцией в `.cpp` короткий комментарий на русском: что она делает.
- Однострочные тела `if` / `for` без фигурных скобок.
- Геттеры строк возвращают `const std::string&` (без лишнего копирования).
- Вместо ручных циклов используем алгоритмы STL: `std::copy_n`, `std::accumulate`.
- Ошибочный индекс — исключение `std::out_of_range`, а не молчаливый возврат 0.

## 4. Теория, которую нужно знать

### 4.1 Наследование

Наследование позволяет создать новый класс (**производный**) на основе существующего (**базового**). Производный класс получает поля и методы базового и добавляет свои.

```cpp
class Student : public Fakultet { ... };
```

- `Fakultet` — базовый класс (родитель).
- `Student` — производный класс (потомок).
- Двоеточие отделяет производный класс от базового.

**Отношение «является» (is-a):** `Student` является `Fakultet` в смысле наследования, то есть содержит всё, что есть в `Fakultet`, и может использоваться там, где ожидается `Fakultet`.

Виды: **простое** наследование (один базовый класс, как у нас) и **множественное** (несколько базовых классов: `class D : public A, public B`).

### 4.2 Модификаторы доступа при наследовании

Права доступа к членам базового класса внутри производного:

| В базовом классе | `public`-наследование | `protected`-наследование | `private`-наследование |
|---|---|---|---|
| `public` | `public` | `protected` | `private` |
| `protected` | `protected` | `protected` | `private` |
| `private` | нет доступа | нет доступа | нет доступа |

Главные правила:
- Права при наследовании можно только **сузить**, но не расширить.
- `private`-члены базового класса **недоступны** в производном напрямую никогда.
- Если модификатор не указан: для `class` по умолчанию `private`, для `struct` по умолчанию `public`.

**Вопрос, который могут задать:** «`faculty_name` в `Fakultet` объявлен `private`. Как же `Student` его использует?»
Ответ: напрямую никак. `Student::print()` вызывает `Fakultet::print()`, а изменить или прочитать название факультета можно через публичные `get_faculty_name()` и `set_faculty_name()`. Если бы поле было `protected`, `Student` мог бы обращаться к нему напрямую. Мы выбрали `private` ради инкапсуляции: база сама отвечает за свои данные.

### 4.3 Конструкторы и деструкторы в иерархии

**Порядок вызова:**
- Создание объекта `Student`: сначала конструктор `Fakultet` (база), потом тело конструктора `Student`.
- Уничтожение: наоборот, сначала деструктор `Student`, потом `Fakultet`.

Принцип: объект строится «снизу вверх» (фундамент, потом надстройка), разрушается «сверху вниз».

**Передача параметров в базовый конструктор** выполняется через список инициализации:

```cpp
Student::Student(const std::string& faculty, int exams)
    : Fakultet(faculty), full_name(""), birth_year(0), exams_count(0), results(nullptr)
{
    this->set_results(nullptr, exams);   // выделяем массив и обнуляем
}
```

Если у базового класса нет конструктора по умолчанию (у нас его нет), производный класс **обязан** явно вызвать нужный конструктор базы, иначе ошибка компиляции.

Порядок инициализации определяется порядком объявления полей в классе, а не порядком в списке инициализации.

Почему `results(nullptr)` в списке: `set_results` делает `delete[] this->results`, а `delete[]` от `nullptr` безопасен. Если оставить указатель неинициализированным, получим удаление мусорного адреса.

### 4.4 Виртуальные функции и полиморфизм

**Виртуальная функция** — функция, объявленная в базовом классе с `virtual` и переопределяемая в производных. Какая версия вызовется, решается **во время выполнения** по реальному типу объекта.

```cpp
Fakultet* p = new Student(...);
p->print();      // вызовется Student::print(), а не Fakultet::print()
```

В нашей программе `print()` объявлен `virtual` в `Fakultet`, а в `Student` переопределён с `override`.

**`override`** — подсказка компилятору: «эта функция должна переопределять виртуальную». Если сигнатура не совпадёт (опечатка, забытый `const`), компилятор выдаст ошибку, а не создаст новую функцию молча.

**Как это работает внутри (vtable):** у класса с виртуальными функциями есть таблица виртуальных функций (vtable), а у каждого объекта скрытый указатель на неё (vptr). Вызов виртуальной функции идёт через этот указатель (косвенный вызов), поэтому он чуть медленнее обычного и требует немного дополнительной памяти.

**Вызов с полным именем отключает виртуальный механизм:** `Fakultet::print()` внутри `Student::print()` вызывает именно версию базового класса. Мы так и делаем: сначала печатаем факультет через базу, потом данные студента.

Класс, содержащий хотя бы одну виртуальную функцию, называется **полиморфным**.

### 4.5 Виртуальный деструктор

```cpp
virtual ~Fakultet();
```

Если удалять объект производного класса через указатель на базовый (`delete p`, где `p` имеет тип `Fakultet*`), а деструктор базы **не** виртуальный, то вызовется только `~Fakultet()`. Деструктор `Student` не выполнится, и динамический массив `results` **утечёт**. Виртуальный деструктор гарантирует цепочку `~Student()` и затем `~Fakultet()`.

Правило: у любого класса, от которого предполагается наследовать, деструктор должен быть виртуальным.

### 4.6 Динамическая память и «правило трёх»

`Student` владеет динамическим массивом `int* results`. Поэтому нужны три вещи:

1. **Деструктор**: `delete[] this->results;` (иначе утечка памяти).
2. **Конструктор копирования**: выделяет **свою** память и копирует значения.
3. **Оператор присваивания**: заменяет старый массив копией чужого.

Если их не написать, компилятор создаст версии по умолчанию, которые копируют **только указатель** (поверхностное копирование). Тогда две копии указывают на один массив, и при уничтожении обеих `delete[]` вызовется дважды для одной памяти (**double free**, крах программы).

**Глубокое копирование** — копируем сами данные в новую память.
**Поверхностное** — копируем только адрес.

**Один метод вместо четырёх копий кода.** Всю работу с массивом делает `set_results`, а конструкторы и `operator=` просто вызывают его:

```cpp
void Student::set_results(const int* marks, int exams)
{
    int* new_results = new int[exams]{};     // 1. сначала выделяем новую память (нули)
    if (marks)
        std::copy_n(marks, exams, new_results);   // 2. копируем значения

    delete[] this->results;                  // 3. и только потом освобождаем старую
    this->results = new_results;
    this->exams_count = exams;
}
```

Порядок «сначала `new`, потом `delete[]`» даёт **безопасность относительно исключений**: если `new` бросит `std::bad_alloc`, старый массив остаётся целым и объект не ломается. Если сначала удалить, а потом выделять, при ошибке выделения объект останется с «висящим» указателем.

`marks == nullptr` означает «нулевые оценки»: так конструктор `Student(faculty, exams)` создаёт пустого студента.

```cpp
Student::Student(const Student& other)
    : Fakultet(other), full_name(other.full_name), birth_year(other.birth_year), exams_count(0), results(nullptr)
{
    this->set_results(other.results, other.exams_count);   // своя память
}
```

Обратите внимание на `Fakultet(other)`: копируется и часть базового класса. Если это забыть, база будет создана конструктором по умолчанию (которого нет, будет ошибка) или потеряет данные.

**Оператор присваивания:**
```cpp
if (this != &other)                   // защита от s = s
{
    Fakultet::operator=(other);       // присваиваем часть базы
    this->full_name = other.full_name;
    this->birth_year = other.birth_year;
    this->set_results(other.results, other.exams_count);
}
return *this;                         // для цепочек a = b = c
```

Проверка `this != &other` нужна: без неё при `s = s` пришлось бы работать с массивом, который сам же освобождаем. Здесь `set_results` сначала копирует, потом удаляет, но проверка всё равно остаётся хорошей практикой и экономит лишнюю работу.

Разница между копированием и присваиванием: конструктор копирования создаёт **новый** объект, оператор присваивания работает с **уже существующим** (поэтому ему надо освободить старые ресурсы).

### 4.7 Исключения при выходе за границы

`get_mark` и `set_mark` при неверном индексе бросают `std::out_of_range("Нет оценки с таким номером.")`:

```cpp
if (index < 0 || index >= this->exams_count)
    throw std::out_of_range("Нет оценки с таким номером.");
```

Почему не `return 0`: возврат нуля неотличим от настоящей оценки 0, и ошибка вызывающего кода остаётся незамеченной. Исключение нельзя проигнорировать случайно, его ловят через `try { ... } catch (const std::out_of_range&) { ... }`.

## 5. Разбор кода по частям

### 5.1 Fakultet

Хранит только название факультета. Имеет:
- конструктор с параметром (название);
- виртуальный деструктор (пустой, но виртуальный);
- `get_faculty_name()` (возвращает `const std::string&`), `set_faculty_name()`;
- виртуальный `print()`, который выводит `Faculty: ...`.

### 5.2 Student

**Поля:** `full_name`, `birth_year`, `exams_count`, `results` (указатель на массив оценок).

**Два конструктора с параметрами:**
- `Student(faculty, exams)`: пустой студент с `exams` нулевыми оценками (используется в `main`, потом вызывается `input()`);
- `Student(faculty, name, year, marks, exams)`: сразу со всеми данными, оценки копируются из массива `marks`.

Оба вызывают `set_results`.

**`set_results(marks, exams)`:** единственное место, где выделяется и освобождается массив оценок (см. 4.6).

**`average()`:** `std::accumulate` считает сумму, затем деление на количество; если экзаменов 0, возвращает 0 (защита от деления на ноль). Приведение `static_cast<double>` нужно, чтобы деление не было целочисленным (иначе 17/2 дало бы 8, а не 8.5).

**`input()`:** `std::getline(std::cin >> std::ws, this->full_name)`. Ф.И.О. содержит пробелы, а `cin >>` читает до пробела, поэтому нужен `getline`. `std::ws` пропускает оставшийся в буфере символ новой строки после предыдущего ввода числа (иначе `getline` прочитал бы пустую строку).

**`get_mark(index)` и `set_mark(index, mark)`:** проверяют выход индекса за границы массива и бросают `std::out_of_range`.

**`print()`:** сначала `Fakultet::print()`, потом свои поля, потом средний балл через `std::format("{:.2f}", ...)` (два знака после запятой).

### 5.3 main

```
do {
    ввести факультет, количество студентов, количество экзаменов
    если данные некорректны → сообщение об ошибке
    иначе:
        Student** students = new Student*[count];   // массив указателей
        для каждого студента: new Student(...), input()
        вывести всех: students[i]->print()
        Student copy(*students[0]);                  // проверка копирования
        copy.print()
        delete каждого студента, потом delete[] students
    спросить Continue? (y/n)
} while (choice == 'y' || choice == 'Y');
```

**Почему `Student**`:** у `Student` нет конструктора по умолчанию, поэтому создать `new Student[count]` нельзя. Вместо этого создаём массив **указателей** и каждый объект отдельно через `new`.

**Освобождение памяти:** каждый `new Student` парный `delete`, массив указателей `new Student*[]` парный `delete[]`. Порядок: сначала объекты, потом массив указателей.

## 6. Возможные вопросы на защите

**1. Что такое наследование и зачем оно нужно?**
Механизм создания нового класса на основе существующего. Нужно для повторного использования кода и для построения иерархий («является»). Общие данные и поведение лежат в базовом классе, особенности в производных.

**2. Чем простое наследование отличается от множественного?**
При простом один базовый класс, при множественном несколько (`class D : public A, public B`). Конструкторы баз вызываются в порядке перечисления в объявлении класса. Проблема множественного наследования: «ромб» (общий предок), решается виртуальным наследованием.

**3. В каком порядке вызываются конструкторы и деструкторы?**
Конструкторы от базового к производному, деструкторы в обратном порядке.

**4. Зачем `: Fakultet(faculty)` в конструкторе `Student`?**
У `Fakultet` нет конструктора по умолчанию, поэтому нужно явно передать параметры базовому конструктору.

**5. Что будет, если убрать `virtual` у деструктора `Fakultet`?**
При удалении `Student` через `Fakultet*` не вызовется `~Student()`, массив `results` не освободится, будет утечка памяти (и это неопределённое поведение).

**6. Что делает `override`?**
Проверка на этапе компиляции, что функция действительно переопределяет виртуальную из базового класса.

**7. Что такое полиморфизм?**
Возможность вызывать через указатель или ссылку на базовый класс функцию, версия которой выбирается по реальному типу объекта во время выполнения (виртуальные функции).

**8. Что такое vtable?**
Таблица указателей на виртуальные функции класса. Каждый объект полиморфного класса хранит скрытый указатель на эту таблицу, по нему выбирается нужная версия при вызове.

**9. Зачем конструктор копирования и что такое глубокое копирование?**
Потому что класс владеет динамической памятью. Глубокое копирование создаёт для копии собственный массив, а не копирует указатель. Иначе два объекта делили бы одну память и при удалении был бы двойной `delete[]`.

**10. Когда вызывается конструктор копирования?**
При создании объекта из другого (`Student copy(s)`), при передаче объекта в функцию по значению и при возврате по значению.

**11. Чем конструктор копирования отличается от оператора присваивания?**
Конструктор создаёт новый объект, оператор присваивания меняет существующий (должен освободить старые ресурсы и защититься от самоприсваивания).

**12. Что такое правило трёх?**
Если классу нужен один из трёх (деструктор, конструктор копирования, оператор присваивания), то, скорее всего, нужны все три.

**13. Почему `print()` в `Student` вызывает `Fakultet::print()`?**
Чтобы не дублировать вывод факультета и показать явный вызов версии базового класса (с полным именем виртуальный механизм не применяется).

**14. Что такое срезка объектов (slicing)?**
Если присвоить объект `Student` объекту типа `Fakultet` **по значению** (`Fakultet f = student;`), скопируется только часть `Fakultet`, остальное «срежется». Поэтому полиморфизм работает через указатели и ссылки, а не через значения.

**15. Почему в `Student` нет прямого доступа к `faculty_name`?**
Поле `private`. Доступ только через публичные методы. При `protected` был бы прямой доступ в потомке.

**16. Что такое `this`?**
Неявный указатель на текущий объект внутри нестатического метода. Используется, например, в `this != &other`, а также в `this->full_name`, чтобы сразу видно было, что это член класса.

**17. Зачем `const` после `print()`?**
Метод не изменяет объект, его можно вызывать для константных объектов и через константные ссылки. Для `override` сигнатуры (включая `const`) должны совпадать.

**18. Почему `Student**`, а не массив `Student`?**
Нет конструктора по умолчанию, поэтому `new Student[n]` не скомпилируется. Массив указателей позволяет создавать каждый объект с нужными параметрами.

**19. Что будет без `std::ws` в `input()`?**
После `cin >> число` в буфере остаётся `\n`, `getline` сразу прочитает его как пустую строку, и имя будет пустым.

**20. Можно ли наследовать от `union`?**
Нет, объединение не может быть ни базовым, ни производным классом.

**21. Почему в `set_results` сначала `new`, потом `delete[]`?**
Если выделение памяти завершится исключением, старый массив ещё не удалён и объект остаётся корректным (безопасность относительно исключений). Обратный порядок оставил бы объект с указателем на освобождённую память.

**22. Зачем `results(nullptr)` в списке инициализации конструкторов?**
Конструктор вызывает `set_results`, а тот делает `delete[]` старого указателя. Для `nullptr` это безопасно, для неинициализированного указателя было бы неопределённое поведение.

**23. Почему `get_mark` бросает исключение, а не возвращает 0?**
0 может быть настоящей оценкой, поэтому ошибка индекса скрылась бы. Исключение `std::out_of_range` невозможно не заметить, его нужно обработать.

**24. Почему геттеры возвращают `const std::string&`, а не `std::string`?**
Возврат по константной ссылке не копирует строку, а `const` запрещает изменять поле через возвращённую ссылку. Ссылка валидна, пока жив объект.

**25. Зачем `std::copy_n` и `std::accumulate` вместо цикла?**
Короче, понятнее по смыслу и меньше шансов ошибиться с границами. Это стандартные алгоритмы из `<algorithm>` и `<numeric>`.

## 7. Быстрая шпаргалка

- Наследование: `class Derived : public Base`.
- Конструкторы: база → производный. Деструкторы: производный → база.
- Параметры базе передаются через список инициализации.
- `virtual` + `override` дают полиморфизм; `virtual ~Base()` обязателен для базовых классов.
- Класс владеет `new`-памятью → деструктор + конструктор копирования + `operator=`.
- Копирование **глубокое**, с защитой от `a = a`.
- Одно место работы с массивом (`set_results`): сначала `new`, потом `delete[]`.
- Неверный индекс → `std::out_of_range`.
- `Base::method()` отключает виртуальность и вызывает версию базы.
