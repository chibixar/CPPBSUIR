## 1. Условие задачи

> Разработать класс `Fakultet`, порождающий класс `Student`. Класс `Fakultet` включает компоненты-данные: наименование факультета. Класс `Student` включает компоненты-данные: Ф.И.О. студента, год рождения, результаты сдачи последней сессии.

Что из этого следует:

| Требование | Как выполнено |
|---|---|
| Базовый класс `Fakultet` | Поле `faculty_name` |
| Производный класс `Student` | `public`-наследование от `Fakultet` |
| Ф.И.О. | `std::string full_name` |
| Год рождения | `int birth_year` |
| Результаты последней сессии | `int* results` (динамический массив) и `int exams_count` |
| Демонстрация наследования | `Student::print()` вызывает `Fakultet::print()`; конструктор `Student` вызывает конструктор `Fakultet` |
| Демонстрация полиморфизма | `virtual print()`, чисто виртуальный `input()`, `override`, виртуальный деструктор; в `main` студенты хранятся и обрабатываются через указатели `Fakultet*` |
| Динамическая память | Массив оценок + массив указателей на студентов в `main` |
| Зацикливание программы | `do { ... } while (choice == 'y' || choice == 'Y')` |

## 2. Что делает программа и пример запуска

1. Пользователь вводит название факультета, количество студентов и количество экзаменов в последней сессии.
2. Для каждого студента создаётся объект `Student` (через `new`), указатель на него хранится как `Fakultet*`; пользователь вводит Ф.И.О., год рождения и оценки (виртуальный `input()`).
3. Программа выводит всех студентов: факультет, Ф.И.О., год рождения, оценки, средний балл.
4. Создаётся **копия** первого студента (проверка конструктора копирования) и выводится.
5. Вся динамическая память освобождается.
6. Программа спрашивает `Continue? (y/n)`; при `y` всё повторяется.

Реальный прогон (ввод: `FAMCS`, 2 студента, 2 экзамена, `Ivanov Ivan 2005 9 8`, `Petrov Petr 2004 7 10`, затем `n`):

```
Enter faculty name: Enter number of students: Enter number of exams in the last session:
Student 1:
Enter full name: Enter birth year: Enter mark for exam 1: Enter mark for exam 2:
Student 2:
Enter full name: Enter birth year: Enter mark for exam 1: Enter mark for exam 2:

Students list:

Faculty: FAMCS
Full name: Ivanov Ivan
Birth year: 2005
Session results: 9 8
Average mark: 8.50

Faculty: FAMCS
Full name: Petrov Petr
Birth year: 2004
Session results: 7 10
Average mark: 8.50

Copy of the first student:
Faculty: FAMCS
Full name: Ivanov Ivan
Birth year: 2005
Session results: 9 8
Average mark: 8.50

Continue? (y/n):
```

(В консоли приглашения и ввод идут на одной строке, поэтому в логе при подаче ввода из файла строки слиплись.)

Некорректный ввод: если `count <= 0` или `exams < 0`, выводится `Error: Invalid number of students or exams.`, затем снова вопрос `Continue?`.

## 3. Структура проекта и сборка

| Файл | Что внутри |
|------|-----------|
| `fakultet.h` | Условие в комментарии, объявление класса `Fakultet` |
| `fakultet.cpp` | Реализация методов `Fakultet` |
| `student.h` | Объявление класса `Student` (подключает `fakultet.h`) |
| `student.cpp` | Реализация методов `Student` |
| `main.cpp` | Ввод данных, цикл, создание студентов, вывод, проверка копии |

**Правило: на каждый класс свой заголовок и свой файл методов.** В заголовке интерфейс (что класс умеет), в `.cpp` реализация (как он это делает). Заголовок подключается через `#pragma once`, чтобы не включаться дважды. `student.h` содержит `#include "fakultet.h"`, потому что для `class Student : public Fakultet` компилятору нужно **полное** определение базового класса (предварительного объявления недостаточно). `main.cpp` подключает только `student.h`, а `fakultet.h` попадает в него транзитивно.

Зависимости:

```
main.cpp ──▶ student.h ──▶ fakultet.h
student.cpp ──▶ student.h
fakultet.cpp ──▶ fakultet.h
```

Сборка (нужен C++20 из-за `std::format`):

```
g++ -std=c++20 -Wall -Wextra -o lab3 main.cpp fakultet.cpp student.cpp
```

Что делает компилятор: каждый `.cpp` компилируется отдельно в объектный файл (препроцессор вставляет `#include`, компилятор транслирует), затем **линковщик** собирает объектные файлы в программу и сопоставляет вызовы функций с их определениями. Если забыть `student.cpp` или `fakultet.cpp` в команде, будет ошибка линковки `undefined reference to Student::...` (или `Fakultet::...`), а не ошибка компиляции.

Если компилятор старый и не знает `std::format`, замена: `std::cout << std::fixed << std::setprecision(2) << average()` (нужен `<iomanip>`).

## 4. Стиль кода (согласован с лабой про транспорт)

- Имена методов и полей в `snake_case`: `get_full_name`, `exams_count`.
- К членам класса обращаемся через `this->`.
- Над каждой функцией в `.cpp` короткий комментарий на русском: что она делает.
- Однострочные тела `if` / `for` без фигурных скобок. Многострочные в скобках.
- Геттеры строк возвращают `const std::string&` (без копирования).
- Вместо ручных циклов стандартные алгоритмы: `std::copy_n`, `std::accumulate`.
- Ошибочный индекс: исключение `std::out_of_range`, а не молчаливый `return 0`.
- Каждому классу свой заголовок и свой `.cpp` (`fakultet.h/.cpp`, `student.h/.cpp`).
- Вся работа с динамическим массивом сосредоточена в одном методе `set_results`.
- Сначала создаём новое, потом освобождаем старое (безопасность относительно исключений).

Зачем единый стиль: код читается как одно целое, меньше путаницы, преподавателю проще проверять.

## 6. Теория

### 6.1 Класс, объект, инкапсуляция

**Класс** — пользовательский тип данных: описание полей (данные) и методов (поведение). **Объект** — экземпляр класса, конкретная область памяти.

Три столпа ООП:
- **Инкапсуляция**: данные скрыты (`private`), доступ через методы (`get_`/`set_`). Класс сам отвечает за корректность своих данных (например, `set_mark` проверяет индекс).
- **Наследование**: новый класс на основе существующего.
- **Полиморфизм**: один интерфейс, разные реализации (виртуальные функции).

Иногда добавляют четвёртый: **абстракция** (выделение существенного, скрытие деталей).

### 6.2 Спецификаторы доступа

| Спецификатор | Из самого класса | Из потомка | Снаружи |
|---|---|---|---|
| `private` | да | нет | нет |
| `protected` | да | да | нет |
| `public` | да | да | да |

Для `class` по умолчанию `private`, для `struct` по умолчанию `public`. Больше разницы между `class` и `struct` нет.

Доступ проверяется **компилятором** на этапе компиляции, а не во время выполнения (память всё равно общая, это защита от ошибок программиста, а не от взлома).

### 6.3 Конструкторы

Конструктор: специальный метод без возвращаемого типа с именем класса; вызывается при создании объекта; приводит объект в корректное состояние.

Виды:
- **по умолчанию** (без параметров). У нас нет ни у `Fakultet`, ни у `Student`: компилятор не создаёт его автоматически, если написан любой другой конструктор. Поэтому `new Student[n]` не компилируется, и `Student` у нас хранятся через указатели.
- **с параметрами**: `Student(faculty, exams)` и `Student(faculty, name, year, marks, exams)`.
- **копирования**: `Student(const Student&)`. Параметр только по ссылке (если бы по значению, для передачи параметра пришлось бы вызвать конструктор копирования, и так до бесконечности).
- **перемещения** (`Student(Student&&)`): в C++11; у нас нет (см. 6.11).

**Список инициализации** (`: Fakultet(faculty), full_name(name), ...`):
- единственный способ передать параметры конструктору базового класса;
- единственный способ инициализировать `const`-поля и поля-ссылки;
- эффективнее присваивания в теле: поле строится сразу нужным значением, а не «пустым, потом присвоить».
- Порядок инициализации определяется **порядком объявления полей в классе**, а не порядком в списке. Если они расходятся, компилятор предупреждает (`-Wreorder`). У нас порядок совпадает.

**`explicit`**: запрещает неявное преобразование через одноаргументный конструктор. `Fakultet(const std::string&)` у нас не `explicit`, поэтому строку можно неявно превратить в `Fakultet`. Хорошая практика: `explicit Fakultet(const std::string& name);`. Для `Student` с двумя и более параметрами это не критично.

**Делегирующие конструкторы** (C++11): один конструктор вызывает другой в списке инициализации. У нас похожую роль играет `set_results`, который вызывают все конструкторы.

### 6.4 Деструктор

`~Student()`: вызывается автоматически при уничтожении объекта (выход из области видимости, `delete`). Освобождает ресурсы, которыми объект владеет (у нас `delete[] this->results`). Один на класс, без параметров, не возвращает значения.

После выполнения тела деструктора компилятор автоматически вызывает деструкторы **полей** (`full_name`) и затем деструктор **базового класса** (`~Fakultet`). Вручную их вызывать не нужно.

### 6.5 Наследование

```cpp
class Student : public Fakultet { ... };
```

Производный класс получает поля и методы базового и добавляет свои. **Отношение «является» (is-a)**: `Student` можно использовать там, где ожидается `Fakultet` (по указателю или ссылке).

Виды наследования по числу баз: простое (одна база, у нас) и множественное (`class D : public A, public B`).

Виды по модификатору:

| В базе | `public`-наследование | `protected`-наследование | `private`-наследование |
|---|---|---|---|
| `public` | `public` | `protected` | `private` |
| `protected` | `protected` | `protected` | `private` |
| `private` | нет доступа | нет доступа | нет доступа |

Главные правила:
- Права при наследовании можно только сузить, не расширить.
- `private`-члены базы недоступны в потомке **никогда** (они в объекте есть, но имя недоступно).
- Если модификатор не указан: для `class` — `private`, для `struct` — `public`.
- Только `public`-наследование моделирует «является» и позволяет приводить `Student*` к `Fakultet*` снаружи.
- `private`-наследование читают как «реализован через» (альтернатива композиции).

Что не наследуется: конструкторы, деструктор, `operator=` (у потомка свои, но они **обязаны** вызвать базовые).

**Композиция против наследования.** Строго говоря, «студент является факультетом» семантически неверно: студент **принадлежит** факультету (has-a). Правильная модель: у `Student` поле `Fakultet` или строка. Но условие задачи требует именно иерархию «`Fakultet` порождает `Student`», поэтому делаем так. На защите можно сказать: «Для учебной демонстрации наследования следуем условию; в реальной программе я бы использовал композицию».

### 6.6 Порядок вызова конструкторов и деструкторов

**Создание `Student`:**
1. конструктор `Fakultet` (база);
2. конструкторы полей `Student` в порядке объявления (`full_name`, `birth_year`, ...);
3. тело конструктора `Student`.

**Уничтожение:** обратный порядок: тело `~Student`, деструкторы полей в обратном порядке, `~Fakultet`.

Принцип: строим снизу вверх (фундамент, потом надстройка), разрушаем сверху вниз. Это гарантирует, что при работе конструктора потомка база уже готова, а при разрушении потомок не обращается к уже уничтоженной базе.

Если у базового класса нет конструктора по умолчанию (у нас его нет), потомок **обязан** явно вызвать нужный конструктор базы в списке инициализации, иначе ошибка компиляции.

### 6.7 Виртуальные функции и полиморфизм

**Виртуальная функция**: объявлена в базе с `virtual`, переопределяется в потомке. Какая версия вызовется, решается **во время выполнения** по реальному типу объекта (**позднее связывание**).

```cpp
Fakultet* p = new Student(...);
p->print();      // вызовется Student::print(), а не Fakultet::print()
```

Без `virtual` было бы **раннее связывание**: версия выбирается по типу указателя во время компиляции, и вызвался бы `Fakultet::print()`.

**`override`**: просим компилятор проверить, что функция действительно переопределяет виртуальную. Если сигнатура не совпала (забыли `const`, опечатка в имени, другой тип параметра), ошибка компиляции вместо тихого создания новой функции.

**`final`**: запрещает дальнейшее переопределение (`void print() const final;`) или наследование (`class X final`).

**Как работает (vtable):** у каждого класса с виртуальными функциями есть таблица адресов виртуальных функций (vtable), общая для всех объектов класса. В каждом объекте скрытый указатель `vptr` на таблицу его класса. Вызов `p->print()` идёт через `vptr`: берётся адрес из таблицы и вызывается (косвенный вызов). Цена: небольшой расход памяти (один указатель на объект) и немного медленнее обычного вызова; такие вызовы нельзя встроить (inline) при неизвестном типе.

**Отключение виртуальности:** вызов с полным именем `Fakultet::print()` внутри `Student::print()` идёт к базовой версии без vtable. Мы так и делаем: сначала выводим факультет через базу, потом данные студента.

**Чисто виртуальная функция** (`virtual void print() const = 0;`) делает класс **абстрактным**: объект такого класса создать нельзя, можно только потомков, которые переопределят все чисто виртуальные функции. У нас `Fakultet` **абстрактный**: в нём чисто виртуальный `input()`, поэтому объект `Fakultet` создать нельзя, только `Student`. У `print()` в базе есть тело (обычная виртуальная функция), и `Student::print()` вызывает его явно. Так же устроена лаба про транспорт: `Vehicle` абстрактный, в `main` работают через `Vehicle*`.

**Перегрузка / переопределение / сокрытие:**
- *Перегрузка (overload)*: одно имя, разные параметры, в одном классе, выбор на этапе компиляции.
- *Переопределение (override)*: потомок заменяет виртуальную функцию базы с той же сигнатурой, выбор во время выполнения.
- *Сокрытие (hiding)*: функция потомка с тем же именем, но не виртуальная или с другой сигнатурой, скрывает **все** одноимённые функции базы. Доступ к базовой: `Base::f()`.

Класс, содержащий хотя бы одну виртуальную функцию, называется **полиморфным**. Для виртуальных функций не нужны особые ключевые слова в потомке (она остаётся виртуальной), но `override` обязателен по хорошему тону.

Виртуальными не могут быть: конструкторы, статические функции. Виртуальный вызов внутри конструктора/деструктора **не** уходит в потомка (в этот момент часть потомка ещё не построена или уже разрушена, вызывается версия текущего класса).

### 6.8 Виртуальный деструктор

```cpp
virtual ~Fakultet();
```

Если удалять объект потомка через указатель на базу (`delete p`, где `p` имеет тип `Fakultet*`), а деструктор базы **не** виртуальный, то это **неопределённое поведение**: на практике вызовется только `~Fakultet()`, а `~Student()` нет, и массив `results` утечёт. Виртуальный деструктор гарантирует цепочку `~Student()` → `~Fakultet()`.

Правило: у любого класса, от которого предполагается наследовать и который удаляется по указателю на базу, деструктор должен быть виртуальным. (Или защищённым невиртуальным, если удалять через базу не планируется.)

В нашей программе именно так и удаляется: в `main` массив `Fakultet**`, и `delete students[i]` идёт через указатель на базу. Если убрать `virtual` у `~Fakultet`, AddressSanitizer сразу сообщает `new-delete-type-mismatch` (проверено).

### 6.9 Срезка объектов (slicing)

```cpp
Fakultet f = student;        // скопируется только часть Fakultet, остальное «срежется»
```

При копировании производного объекта в переменную базового типа **по значению** остаётся только база. Поэтому полиморфизм работает через указатели и ссылки, а не через значения. Так же срезка случается при передаче в функцию `void f(Fakultet x)` по значению и при хранении в `std::vector<Fakultet>`.

В нашем коде `Fakultet(other)` в конструкторе копирования `Student` не срезка в плохом смысле: параметр `const Fakultet&` привязывается к базовой части `other`, и копируется именно база, как и задумано.

### 6.10 Динамическая память

- `new T` выделяет память под один объект, `delete p` освобождает. `new T[n]` выделяет массив, освобождается **только** `delete[] p`.
- Смешивание (`new[]` с `delete`, или `new` с `delete[]`) — неопределённое поведение.
- `delete nullptr` и `delete[] nullptr` безопасны (ничего не делают).
- Ошибки: утечка (забыли `delete`), двойное освобождение (double free), обращение к освобождённой памяти (dangling pointer), выход за границы массива.
- `new` при нехватке памяти бросает `std::bad_alloc`. Для отрицательного размера массива бросает `std::bad_array_new_length`.
- `new int[exams]{}` выделяет и **обнуляет** массив (value-initialization). `new int[exams]` без `{}` оставляет мусор.
- `new int[0]` законно: вернёт непустой указатель на «нулевой» массив, `delete[]` корректен.
- `nullptr` (C++11): типобезопасный нулевой указатель; лучше `NULL` (макрос, равный целому `0`, из-за чего возникает неоднозначность при перегрузке).

### 6.11 Правило трёх, пяти, нуля

`Student` владеет ресурсом (`int* results`). Поэтому нужны три вещи:
1. **Деструктор**: `delete[] this->results`.
2. **Конструктор копирования**: выделяет **свою** память и копирует значения.
3. **Оператор присваивания**: заменяет старый массив копией чужого.

Если не написать, компилятор создаст версии по умолчанию, которые копируют каждое поле, то есть для указателя **только адрес** (поверхностное копирование, shallow copy). Тогда две копии указывают на один массив, и при уничтожении обеих `delete[]` вызовется дважды для одной памяти (**double free**, крах).

**Глубокое копирование (deep copy)** — копируем сами данные в новую память. **Поверхностное** — копируем адрес.

**Правило пяти (C++11):** к трём добавляются **конструктор перемещения** и **оператор перемещающего присваивания**, чтобы не копировать данные из временных объектов, а забирать указатель. У нас они не написаны: объявление деструктора/копирования отключает автоматическую генерацию перемещения, и временные объекты просто копируются. Это корректно, но чуть медленнее.

**Правило нуля:** если можно, не владеть ресурсами «вручную»: `std::vector<int>` вместо `int*` + `exams_count`, тогда компилятор сам сгенерирует правильные все пять операций. Мы используем `int*` потому что тема лабы — именно динамическая память и глубокое копирование.

**Разница копирования и присваивания:** конструктор копирования создаёт **новый** объект; оператор присваивания меняет **уже существующий**, поэтому должен избавиться от старых ресурсов и защититься от `a = a`.

**Идиома copy-and-swap** (альтернатива): `Student& operator=(Student other) { swap(*this, other); return *this; }` даёт сильную гарантию безопасности и самозащиту «бесплатно», но требует написать `swap`.

Пример нашего метода, через который устроено всё копирование:

```cpp
// Замена всех оценок (marks == nullptr даёт нулевые оценки)
void Student::set_results(const int* marks, int exams)
{
    int* new_results = new int[exams]{};
    if (marks)
        std::copy_n(marks, exams, new_results);

    delete[] this->results;
    this->results = new_results;
    this->exams_count = exams;
}
```

Конструкторы и `operator=` просто вызывают `set_results`, поэтому логика выделения и копирования записана **один раз**.

### 6.12 Безопасность относительно исключений

Три уровня гарантий:
- **базовая**: при исключении нет утечек, объект в корректном (но, возможно, изменённом) состоянии;
- **строгая**: при исключении ничего не изменилось (всё или ничего);
- **nothrow**: функция не бросает исключений.

`set_results` даёт **строгую гарантию** для массива: сначала `new` (может бросить `bad_alloc`, но старый массив не тронут), потом `copy_n` (для `int` не бросает), потом освобождаем старый и подменяем указатель. Обратный порядок («сначала `delete[]`, потом `new`») при ошибке выделения оставил бы объект с «висящим» указателем на освобождённую память.

Нюанс: в `operator=` до вызова `set_results` уже присвоены `faculty_name`, `full_name`, `birth_year`. Если `set_results` бросит исключение, объект окажется частично изменённым. Значит, весь `operator=` даёт **базовую** гарантию. Чтобы получить строгую, достаточно вызвать `set_results` **первым**.

### 6.13 Исключения

```cpp
if (index < 0 || index >= this->exams_count)
    throw std::out_of_range("Нет оценки с таким номером.");
```

- `throw` выбрасывает объект-исключение; выполнение прыгает к ближайшему подходящему `catch` вверх по стеку вызовов.
- **Раскрутка стека (stack unwinding):** при выходе из блока из-за исключения вызываются деструкторы всех локальных объектов (поэтому RAII-объекты не утекают).
- Ловим по константной ссылке: `catch (const std::out_of_range& e) { ... e.what() ... }`. По значению ловить нельзя из-за срезки.
- `std::out_of_range` наследуется от `std::logic_error` ← `std::exception` (заголовок `<stdexcept>`). `catch (const std::exception&)` ловит любое стандартное исключение.
- Почему не `return 0`: 0 может быть настоящей оценкой, ошибка индекса скрылась бы. Исключение нельзя проигнорировать случайно.
- Если исключение нигде не поймано, вызывается `std::terminate` и программа аварийно завершается.
- Исключение из конструктора допустимо: объект считается не созданным, его деструктор не вызывается, но уже построенные базы и поля уничтожаются. Поэтому в наших конструкторах `results(nullptr)` в списке инициализации и последующий `set_results` безопасны.

Сообщение исключения написано по-русски. В консоли Windows может понадобиться кодировка UTF-8 (`chcp 65001`), иначе вместо букв будут «кракозябры».

### 6.14 const-корректность

- `const` после списка параметров (`double average() const`): метод не меняет объект; его можно вызывать у константных объектов и через `const`-ссылки. `override` требует совпадения `const` в сигнатуре.
- `const std::string&` в параметрах: не копируем и не меняем.
- `const std::string& get_full_name() const`: возвращаем ссылку на внутреннее поле без копии; `const` не позволяет изменить поле через ссылку. Ссылка действительна, пока жив объект.
- `const int* marks`: данные по указателю менять нельзя (указатель на константу). Не путать с `int* const` (константный указатель).

### 6.15 Ссылки и указатели

| | Ссылка | Указатель |
|---|---|---|
| Может быть пустой | нет | да (`nullptr`) |
| Можно «переприсвоить» | нет (привязана навсегда) | да |
| Синтаксис доступа | `x.f()` | `p->f()` |
| Арифметика | нет | да |

Параметры по константной ссылке удобны: нет копирования и нет возможности передать «ничего».

### 6.16 `this`

Неявный указатель на текущий объект внутри нестатического метода. Использования: `this != &other` (самоприсваивание), `return *this` (цепочки `a = b = c`), и просто `this->full_name` для читаемости (сразу видно, что это поле, а не локальная переменная).

### 6.17 Ввод-вывод

- `std::cin >> x` читает до пробела; пропускает ведущие пробельные символы; оставляет в буфере символ новой строки.
- `std::getline(std::cin, s)` читает всю строку до `\n`. Ф.И.О. содержит пробелы, поэтому нужен именно `getline`.
- `std::ws` — манипулятор, пропускающий пробельные символы. Запись `std::getline(std::cin >> std::ws, s)` пропускает оставшийся после предыдущего `cin >> число` символ `\n`; без него `getline` прочитал бы пустую строку и имя было бы пустым.
- Состояния потока: `good`, `fail`, `eof`, `bad`. Если ввести буквы вместо числа, `cin` переходит в `fail`, и все дальнейшие чтения не работают, пока не вызвать `cin.clear()` и не сбросить мусор через `cin.ignore(...)`. В лабе №3 такой защиты нет (см. раздел 9); в лабе №4 для меню она есть.
- `std::cout << "...\n"` быстрее, чем `std::endl` (тот ещё и сбрасывает буфер).

### 6.18 `std::format` и алгоритмы STL

- `std::format("{:.2f}", x)` — форматирование (C++20, `<format>`): `{}` место подстановки, `:.2f` — дробное число с двумя знаками.
- `std::copy_n(src, n, dst)` копирует `n` элементов (`<algorithm>`).
- `std::accumulate(begin, end, 0)` сумма элементов (`<numeric>`). Начальное значение `0` типа `int` задаёт тип суммы; если бы было `0.0`, считалось бы в `double`.
- Указатели подходят как итераторы: `results` — начало, `results + exams_count` — конец.

### 6.19 Многофайловый проект

- **Объявление** (declaration) говорит компилятору, что функция/класс существует. **Определение** (definition) задаёт реализацию.
- **Правило одного определения (ODR):** определение функции должно быть одно на всю программу. Поэтому определения кладём в `.cpp`, а в заголовок только объявления. (Определения внутри класса, в заголовке, неявно `inline`.)
- `#pragma once` и классические защитные макросы `#ifndef X_H / #define X_H / #endif` предотвращают повторное включение заголовка в один `.cpp`.
- Заголовок должен подключать то, что ему нужно для объявлений (`<string>`), `.cpp` — всё остальное.
- Предварительное объявление (`class X;`) достаточно, если нужен только указатель/ссылка. Для наследования (`class Student : public Fakultet`) нужно полное определение базы, поэтому `student.h` включает `fakultet.h`.
- Принцип «один класс — один заголовок и один `.cpp`»: меньше конфликтов, быстрее пересборка (изменение `student.cpp` не требует перекомпиляции `fakultet.cpp`), проще повторно использовать класс в другом проекте (достаточно скопировать пару файлов).
- Заголовок самодостаточен: `fakultet.h` можно включить в пустой `.cpp`, и он скомпилируется (подключает всё, что нужно для своих объявлений).

### 6.20 Множественное наследование и «ромб»

`class D : public B, public C` — D содержит подобъекты обеих баз. Конструкторы баз вызываются в порядке перечисления в объявлении. Проблема «ромба»: если `B` и `C` оба наследуют `A`, то в `D` два экземпляра `A` и неоднозначность `d.a_member`. Решение: **виртуальное наследование** (`class B : virtual public A`), тогда `A` один, а его конструктор вызывает самый производный класс. В лабе у нас простое наследование.

### 6.21 `static` и `friend` (на случай вопроса)

- `static`-поле принадлежит классу, а не объекту; определяется один раз вне класса (`int Student::total = 0;`). `static`-метод не имеет `this`.
- `friend`-функция/класс получает доступ к `private`-членам. Нарушает инкапсуляцию, применять редко. У нас `friend` нигде не нужен.

Fakultet включает компоненты данные: наименование факультета, Класс

Разбор:
- Комментарий с условием: просто текст (лежит в заголовке базового класса).
- `#pragma once`: однократное включение.
- `#include <string>`: нужен для `std::string` в объявлениях.
- Поле `faculty_name` `private`. Конструктор принимает `const std::string&` (без копирования при передаче). Деструктор `virtual`. `get_faculty_name` возвращает константную ссылку и сам `const`. `set_faculty_name` меняет поле. `print` виртуальный и `const`.

### 7.4 `student.cpp`

```cpp
#include "student.h"
#include <algorithm>
#include <format>
#include <iostream>
#include <numeric>
#include <stdexcept>

// Создание студента с нулевыми оценками
Student::Student(const std::string& faculty, int exams)
    : Fakultet(faculty), full_name(""), birth_year(0), exams_count(0), results(nullptr)
{
    this->set_results(nullptr, exams);
}

// Создание студента со всеми данными
Student::Student(const std::string& faculty, const std::string& name,
                 int year, const int* marks, int exams)
    : Fakultet(faculty), full_name(name), birth_year(year), exams_count(0), results(nullptr)
{
    this->set_results(marks, exams);
}

// Конструктор копирования (глубокая копия)
Student::Student(const Student& other)
    : Fakultet(other), full_name(other.full_name), birth_year(other.birth_year), exams_count(0), results(nullptr)
{
    this->set_results(other.results, other.exams_count);
}

// Освобождение массива оценок
Student::~Student()
{
    delete[] this->results;
}

// Оператор присваивания
Student& Student::operator=(const Student& other)
{
    if (this != &other)
    {
        Fakultet::operator=(other);
        this->full_name = other.full_name;
        this->birth_year = other.birth_year;
        this->set_results(other.results, other.exams_count);
    }

    return *this;
}

// Получение Ф.И.О.
const std::string& Student::get_full_name() const
{
    return this->full_name;
}

// Получение года рождения
int Student::get_birth_year() const
{
    return this->birth_year;
}

// Получение количества экзаменов
int Student::get_exams_count() const
{
    return this->exams_count;
}

// Получение оценки по индексу
int Student::get_mark(int index) const
{
    if (index < 0 || index >= this->exams_count)
        throw std::out_of_range("Нет оценки с таким номером.");

    return this->results[index];
}

// Изменение Ф.И.О.
void Student::set_full_name(const std::string& name)
{
    this->full_name = name;
}

// Изменение года рождения
void Student::set_birth_year(int year)
{
    this->birth_year = year;
}

// Изменение оценки по индексу
void Student::set_mark(int index, int mark)
{
    if (index < 0 || index >= this->exams_count)
        throw std::out_of_range("Нет оценки с таким номером.");

    this->results[index] = mark;
}

// Замена всех оценок (marks == nullptr даёт нулевые оценки)
void Student::set_results(const int* marks, int exams)
{
    int* new_results = new int[exams]{};
    if (marks)
        std::copy_n(marks, exams, new_results);

    delete[] this->results;
    this->results = new_results;
    this->exams_count = exams;
}

// Вычисление среднего балла
double Student::average() const
{
    if (this->exams_count == 0)
        return 0.0;

    int sum = std::accumulate(this->results, this->results + this->exams_count, 0);

    return static_cast<double>(sum) / this->exams_count;
}

// Ввод данных студента
void Student::input()
{
    std::cout << "Enter full name: ";
    std::getline(std::cin >> std::ws, this->full_name);

    std::cout << "Enter birth year: ";
    std::cin >> this->birth_year;

    for (int i = 0; i < this->exams_count; i++)
    {
        std::cout << "Enter mark for exam " << i + 1 << ": ";
        std::cin >> this->results[i];
    }
}

// Вывод данных студента
void Student::print() const
{
    Fakultet::print();

    std::cout << "Full name: " << this->full_name << "\n";
    std::cout << "Birth year: " << this->birth_year << "\n";
    std::cout << "Session results: ";

    for (int i = 0; i < this->exams_count; i++)
        std::cout << this->results[i] << " ";

    std::cout << "\nAverage mark: " << std::format("{:.2f}", this->average()) << "\n";
}
```

Разбор по функциям:

**`Student(faculty, exams)`**: список инициализации: сначала база `Fakultet(faculty)`; `full_name("")`, `birth_year(0)`, `exams_count(0)`, `results(nullptr)`. В теле `set_results(nullptr, exams)` выделяет `exams` нулей. Почему `results(nullptr)`: `set_results` делает `delete[] this->results`, а для неинициализированного указателя это было бы неопределённое поведение, для `nullptr` безопасно.

**`Student(faculty, name, year, marks, exams)`**: то же, но с данными; оценки копируются из `marks`.

**Конструктор копирования**: `Fakultet(other)` копирует базовую часть, поля копируются, оценки копируются через `set_results(other.results, other.exams_count)`. Свой массив.

**Деструктор**: `delete[] this->results`. Строки очистятся сами.

**`operator=`**: `if (this != &other)` защита от `s = s`; `Fakultet::operator=(other)` присваивает базу (без этого часть базы осталась бы старой); поля; `set_results`. `return *this` для цепочек.

**`get_mark`, `set_mark`**: проверка границ, `throw std::out_of_range`.

**`set_results`**: см. 6.11. Три шага: выделить и обнулить; при наличии источника скопировать; освободить старое и подменить указатель.

**`average`**: если оценок нет, 0.0; иначе сумма через `accumulate`, `static_cast<double>` чтобы деление было дробным (17/2 даёт 8, а `17.0/2` даёт 8.5).

**`input`**: `getline` с `ws`, год, цикл по оценкам с нумерацией с 1 (`i + 1`).

**`print`**: сначала `Fakultet::print()` (явный вызов версии базы), потом поля, оценки через пробел, средний балл с двумя знаками.

### 7.5 `main.cpp`

```cpp
#include "student.h"
#include <iostream>
#include <string>

int main()
{
    char choice;

    do
    {
        std::string faculty;
        int count, exams;

        std::cout << "Enter faculty name: ";
        std::getline(std::cin >> std::ws, faculty);

        std::cout << "Enter number of students: ";
        std::cin >> count;

        std::cout << "Enter number of exams in the last session: ";
        std::cin >> exams;

        // Проверка корректности введённых чисел
        if (count <= 0 || exams < 0)
        {
            std::cout << "Error: Invalid number of students or exams.\n";
        }
        else
        {
            // Массив указателей на базовый класс: студентов обрабатываем полиморфно
            Fakultet** students = new Fakultet*[count];

            for (int i = 0; i < count; i++)
            {
                std::cout << "\nStudent " << i + 1 << ":\n";

                students[i] = new Student(faculty, exams);
                students[i]->input();
            }

            std::cout << "\nStudents list:\n";

            for (int i = 0; i < count; i++)
            {
                std::cout << "\n";
                students[i]->print();
            }

            // Проверка конструктора копирования (приведение базового указателя к Student)
            Student copy(*dynamic_cast<Student*>(students[0]));

            std::cout << "\nCopy of the first student:\n";
            copy.print();

            for (int i = 0; i < count; i++)
                delete students[i];

            delete[] students;
        }

        std::cout << "\nContinue? (y/n): ";
        std::cin >> choice;
        std::cout << "\n";

    } while (choice == 'y' || choice == 'Y');

    return 0;

```

Разбор:
- Внешний `do-while` — зацикливание программы.
- Ввод факультета через `getline` (может быть с пробелами).
- Проверка `count <= 0 || exams < 0`: защита от `new Student*[count]` с неверным размером и от отрицательного размера массива в `set_results`.
- `Fakultet** students = new Fakultet*[count]`: массив **указателей на базовый класс**. Нельзя `new Student[count]` (нет конструктора по умолчанию), а хранение через базовый указатель включает полиморфизм: `input()`, `print()` и деструктор вызываются по реальному типу объекта.
- Цикл создания: `new Student(faculty, exams)` присваивается указателю `Fakultet*` (неявное приведение к базе допустимо), затем виртуальный `input()` вызывает `Student::input()`.
- Вывод всех: `students[i]->print()` через `Fakultet*`: виртуальный вызов, выполняется `Student::print()`.
- `Student copy(*dynamic_cast<Student*>(students[0]))`: у `Fakultet*` нет нужного конструктора копирования `Student`, поэтому указатель на базу безопасно приводим вниз через `dynamic_cast` (работает, потому что класс полиморфный), разыменовываем и вызываем конструктор копирования `Student`.
- Освобождение: сначала каждый `delete students[i]` (через `Fakultet*`; благодаря виртуальному деструктору вызывается `~Student`, он освобождает `results`), потом `delete[] students`. Порядок важен: если удалить массив указателей первым, потеряем адреса объектов (утечка).
- `copy` — локальный объект, уничтожится автоматически в конце блока `else`.
- Вопрос `Continue?`: читаем `char`, повторяем при `y`/`Y`.

## 8. Трассировки выполнения

### 8.1 Создание студента `new Student("FAMCS", 2)`

1. `new` выделяет память под объект `Student` (подобъект `Fakultet` + поля).
2. Вызывается `Fakultet("FAMCS")`: инициализирует `faculty_name`, устанавливает `vptr`.
3. Инициализируются поля `Student`: `full_name = ""`, `birth_year = 0`, `exams_count = 0`, `results = nullptr`. `vptr` переключается на vtable `Student`.
4. Тело: `set_results(nullptr, 2)`: `new int[2]{}` → `{0, 0}`; `delete[] nullptr` (ничего); `results` указывает на `{0,0}`; `exams_count = 2`.

### 8.2 Копирование `Student copy(*students[0])`

1. Вызывается `Student(const Student&)`.
2. `Fakultet(other)`: копирует `faculty_name`.
3. Копируются `full_name`, `birth_year`; `exams_count(0)`, `results(nullptr)`.
4. `set_results(other.results, other.exams_count)`: `new int[2]{}`, `copy_n` значений, `delete[] nullptr`, указатель на **новую** память.
5. Результат: `copy.results != students[0]->results`, значения равны; после удаления оригинала копия цела.

### 8.3 Присваивание `a = b` (оба уже существуют)

1. `this != &other` → да.
2. `Fakultet::operator=`: `faculty_name = b.faculty_name`.
3. `full_name`, `birth_year` скопированы.
4. `set_results(b.results, b.exams_count)`: новая память, копия значений, старый массив `a` освобождён.
5. `return *this`.

При `a = a` пункт 1 даёт «нет», и ничего не делается.

### 8.4 Уничтожение `delete students[i]`

1. `students[i]` указывает на `Student`; вызывается `~Student()`: `delete[] results`.
2. Автоматически уничтожаются поля (`full_name`).
3. Автоматически вызывается `~Fakultet()`, затем уничтожается `faculty_name`.
4. Память объекта возвращается системе.

### 8.5 Что видит полиморфизм (так работает `main`)

```cpp
Fakultet* p = new Student(faculty, exams);
p->input();      // vptr → vtable Student → Student::input()
p->print();      // vptr → vtable Student → Student::print()
delete p;        // vptr → ~Student → ~Fakultet (виртуальный деструктор)
```

У `p` статический тип `Fakultet*`, динамический `Student`; версии функций выбираются по динамическому типу.

## 11. Вопросы и ответы

### А. Наследование

**1. Что такое наследование и зачем оно нужно?**
Механизм создания нового класса на основе существующего. Нужно для повторного использования кода и построения иерархий «является». Общее лежит в базе, особенности в потомках.

**2. Чем простое наследование отличается от множественного?**
Простое: одна база. Множественное: несколько (`class D : public A, public B`). Конструкторы баз вызываются в порядке перечисления в объявлении. Проблема: «ромб» (общий предок), решается виртуальным наследованием.

**3. Какие виды наследования по доступу?**
`public`, `protected`, `private`. Таблица в 6.5. Для «является» используют `public`.

**4. Что наследуется, а что нет?**
Наследуются поля и методы (с учётом доступа). Не наследуются конструкторы, деструктор, оператор присваивания (потомок пишет свои и обязан вызвать базовые).

**5. Как `Student` получает доступ к `faculty_name`, если оно `private`?**
Напрямую никак. Через публичные `get_faculty_name()` / `set_faculty_name()` и через `Fakultet::print()`. При `protected` доступ был бы прямой. Выбрали `private` ради инкапсуляции: база сама отвечает за свои данные.

**6. В каком порядке вызываются конструкторы и деструкторы?**
Конструкторы: база, поля потомка в порядке объявления, тело потомка. Деструкторы: в обратном порядке.

**7. Зачем `: Fakultet(faculty)` в конструкторе `Student`?**
У `Fakultet` нет конструктора по умолчанию, поэтому параметры базе нужно передать явно через список инициализации. Без этого ошибка компиляции.

**8. Что если не вызвать конструктор базы явно, а у базы есть конструктор по умолчанию?**
Вызовется он автоматически.

**9. Что значит «`Student` является `Fakultet`»?**
Объект `Student` можно использовать там, где ожидается `Fakultet` (по ссылке или указателю). Семантика is-a.

**10. Правильно ли, что студент «является» факультетом?**
Нет, по смыслу студент принадлежит факультету (has-a, композиция). Но условие задачи требует наследования, поэтому сделано так (см. 6.5).

**11. Можно ли наследовать от `union`? От `final`-класса?**
Нет в обоих случаях. Объединение не может быть ни базой, ни потомком. Класс с `final` наследовать запрещено.

**12. Что такое сокрытие имён?**
Метод потомка с тем же именем, но другой сигнатурой, скрывает все одноимённые методы базы. Доступ к ним: `Base::f()` или `using Base::f;`.

**13. Что такое `protected`? Когда использовать?**
Доступно классу и потомкам, но не снаружи. Использовать осторожно: ослабляет инкапсуляцию. Предпочтительнее `private` + защищённые/публичные методы.

**14. Можно ли привести `Fakultet*` к `Student*`?**
`static_cast` возможно, но небезопасно, если объект на самом деле не `Student`. Безопасно: `dynamic_cast<Student*>(p)` (требует полиморфный класс, вернёт `nullptr`, если тип не подходит).

### Б. Виртуальные функции и полиморфизм

**15. Что такое полиморфизм?**
Вызов через указатель/ссылку на базу функции, версия которой выбирается по реальному типу объекта во время выполнения.

**16. Что делает `virtual`?**
Включает позднее связывание: выбор версии по динамическому типу.

**17. Что делает `override`?**
Проверка компилятором, что функция переопределяет виртуальную. Поймает забытый `const`, опечатку, другой тип параметра.

**18. Что такое vtable и vptr?**
Vtable: таблица адресов виртуальных функций класса (одна на класс). Vptr: скрытый указатель в каждом объекте на vtable его класса. Вызов виртуальной функции: через vptr берётся адрес из таблицы.

**19. Какова цена виртуальных функций?**
Дополнительный указатель в объекте, косвенный вызов, невозможность встраивания при неизвестном типе.

**20. Почему деструктор базы должен быть виртуальным?**
Иначе `delete p` через указатель на базу — неопределённое поведение (на практике не вызовется `~Student`, утечёт `results`).

**21. Что будет, если убрать `virtual` у деструктора `Fakultet`?**
В нашем `main` объекты удаляются через `Fakultet*`, поэтому не вызовется `~Student()`: массив `results` утечёт, поведение неопределённое. AddressSanitizer показывает `new-delete-type-mismatch` (проверено).

**22. Чем переопределение отличается от перегрузки?**
Перегрузка: одно имя, разные параметры, один класс, выбор при компиляции. Переопределение: та же сигнатура в потомке, выбор в run-time.

**23. Что такое чисто виртуальная функция и абстрактный класс?**
`virtual void f() = 0;`. Класс с такой функцией абстрактный: объект создать нельзя, только потомков, переопределивших все такие функции.

**24. Может ли у абстрактного класса быть конструктор? Тело у чисто виртуальной функции?**
Да и да. Конструктор вызывается из конструкторов потомков. Тело у чисто виртуальной функции можно определить отдельно и вызывать как `Base::f()`.

**25. Может ли конструктор быть виртуальным?**
Нет: при вызове конструктора объект ещё не создан, нет `vptr`. Деструктор может и должен.

**26. Что произойдёт при вызове виртуальной функции из конструктора?**
Вызовется версия текущего конструируемого класса, а не потомка (часть потомка ещё не построена).

**27. Зачем `Fakultet::print()` внутри `Student::print()`?**
Не дублировать вывод факультета и явно вызвать версию базы (полное имя отключает виртуальный механизм, иначе была бы бесконечная рекурсия).

**28. Что такое срезка?**
Копирование производного объекта в переменную базового типа по значению: остаётся только база. Поэтому полиморфизм работает через указатели и ссылки.

**29. Что такое `final`?**
Запрет переопределения виртуальной функции или наследования класса.

**30. Что значит `const` после `print()`?**
Метод не изменяет объект; его можно вызывать у константных объектов. В `override` сигнатуры (включая `const`) должны совпадать.

### В. Память, копирование, правило трёх

**31. Что такое глубокое и поверхностное копирование?**
Глубокое: копируются сами данные в новую память. Поверхностное: копируется только адрес, два объекта делят один массив.

**32. Что будет без конструктора копирования?**
Компилятор создаст версию по умолчанию (поверхностную). Копия и оригинал будут указывать на один массив, при удалении двойной `delete[]` (double free, краш).

**33. Когда вызывается конструктор копирования?**
При создании объекта из другого (`Student copy(s)` или `Student copy = s`), при передаче по значению в функцию, при возврате по значению (если не применена оптимизация).

**34. Чем конструктор копирования отличается от оператора присваивания?**
Конструктор создаёт новый объект. Оператор присваивания меняет существующий: должен освободить старое и защититься от самоприсваивания.

**35. Зачем в `operator=` проверка `this != &other`?**
Защита от `s = s`, лишняя работа и риск при ручном освобождении перед копированием. В нашей реализации `set_results` копирует до удаления, поэтому и без проверки было бы безопасно, но проверка остаётся хорошей практикой.

**36. Зачем `return *this` в `operator=`?**
Для цепочек `a = b = c`; возвращаем ссылку на текущий объект.

**37. Зачем в `operator=` явный `Fakultet::operator=(other)`?**
Иначе часть базы осталась бы старой: компилятор не присваивает базу автоматически, если мы пишем оператор вручную.

**38. Почему параметр конструктора копирования — ссылка?**
Если бы по значению, для передачи параметра нужно было бы вызвать конструктор копирования, и так до бесконечности.

**39. Что такое правило трёх?**
Если классу нужен один из трёх (деструктор, конструктор копирования, оператор присваивания), то, скорее всего, нужны все три.

**40. Что такое правило пяти и нуля?**
Пять: плюс конструктор перемещения и перемещающее присваивание. Ноль: по возможности не владеть ресурсами вручную (контейнеры, умные указатели), тогда ничего писать не нужно.

**41. Что такое move-семантика?**
Для временных объектов вместо копирования данных «забираем» ресурс (копируем указатель и обнуляем его в источнике). Быстро. У нас не реализовано, временные объекты копируются.

**42. Почему `new[]` нужно освобождать `delete[]`?**
`delete[]` знает, что надо вызвать деструкторы всех элементов и освободить весь блок. `delete` на массив — неопределённое поведение.

**43. Что делает `new int[exams]{}`?**
Выделяет массив и заполняет нулями.

**44. Что будет при `exams == 0`?**
`new int[0]` допустим, `delete[]` корректен; `average()` вернёт 0.0 (защита от деления на ноль); цикл ввода не выполнится.

**45. Что будет при отрицательном `exams`?**
`new int[-1]` бросит `std::bad_array_new_length`. В `main` это предотвращено проверкой `exams < 0`.

**46. Зачем `results(nullptr)` в списке инициализации?**
`set_results` делает `delete[]` старого указателя; для `nullptr` это безопасно, для неинициализированного мусора — неопределённое поведение.

**47. Почему в `set_results` сначала `new`, потом `delete[]`?**
Если выделение бросит исключение, старый массив цел (строгая гарантия). Обратный порядок оставил бы висящий указатель.

**48. Что такое утечка памяти? Как найти?**
Выделенная память не освобождена, указатель потерян. Находят AddressSanitizer (`-fsanitize=address`), Valgrind, Visual Studio CRT debug.

**49. Что такое висячий указатель (dangling pointer)?**
Указатель на уже освобождённую память. После `delete` полезно обнулять указатель.

**50. Что такое RAII?**
Ресурс захватывается в конструкторе и освобождается в деструкторе объекта; благодаря этому ресурсы не утекают даже при исключениях. Наш `Student` — простой RAII-класс для массива.

**51. Почему `Fakultet**`, а не массив `Student`?**
Нет конструктора по умолчанию, `new Student[n]` не скомпилируется. Массив указателей позволяет создать каждый объект с нужными параметрами. Тип `Fakultet*` выбран, чтобы работать полиморфно (виртуальные `input`, `print`, деструктор), как `Vehicle*` в лабе про транспорт.

**52. Почему сначала удаляем студентов, потом массив указателей?**
Иначе потеряем адреса и получим утечку (или обращение к освобождённой памяти).

**53. Можно ли заменить `Fakultet**` на контейнер STL?**
Да: `std::vector<std::unique_ptr<Fakultet>>` с `make_unique<Student>(...)`. Полиморфизм сохраняется (элементы хранятся по указателю на базу), `delete` писать не нужно. `std::vector<Student>` потеряет полиморфную работу через базу. Но тема лабы — ручное управление памятью.

### Г. Исключения и обработка ошибок

**54. Что делает `throw`? Как ловить?**
Выбрасывает исключение, стек раскручивается до подходящего `catch`. Ловим `catch (const std::out_of_range& e)`.

**55. Почему ловим по ссылке, а не по значению?**
Чтобы не было срезки и лишнего копирования.

**56. Что будет, если исключение не поймано?**
Вызывается `std::terminate`, программа завершается.

**57. Что такое раскрутка стека?**
При прохождении исключения вверх вызываются деструкторы локальных объектов каждого покинутого блока.

**58. Почему `get_mark` бросает исключение, а не возвращает 0?**
0 — валидная оценка; ошибка скрылась бы.

**59. Можно ли бросить исключение из конструктора?**
Да. Объект не считается созданным, его деструктор не вызывается, уже построенные базы и поля уничтожаются.

**60. Можно ли из деструктора?**
Нельзя выпускать наружу: деструкторы по умолчанию `noexcept`, исключение приведёт к `terminate`.

**61. Что такое гарантии безопасности исключений?**
Базовая (без утечек, состояние корректно), строгая (всё или ничего), nothrow.

### Д. Ввод-вывод и мелочи

**62. Что будет без `std::ws` в `input()`?**
После `cin >> число` в буфере остаётся `\n`, `getline` сразу прочитает его как пустую строку, имя будет пустым.

**63. Почему `getline`, а не `cin >>`?**
Ф.И.О. содержит пробелы, `cin >>` читает до первого пробела.

**64. Что будет, если ввести букву вместо числа?**
Поток перейдёт в состояние ошибки, дальнейшие чтения не сработают. Нужна проверка `if (!cin)`, `cin.clear()`, `cin.ignore(...)`.

**65. Зачем `static_cast<double>` в `average()`?**
Без него деление `int / int` целочисленное (17 / 2 = 8).

**66. Что такое `this`?**
Неявный указатель на текущий объект в нестатическом методе. Используется в `this != &other`, `return *this` и для явности `this->field`.

**67. Что такое `#pragma once`?**
Предотвращает повторное включение заголовка в одну единицу трансляции. Альтернатива: `#ifndef/#define/#endif`.

**68. Зачем `const std::string&` в параметрах и возвратах?**
Нет копирования; `const` не даёт изменить.

**69. Что такое список инициализации и когда он обязателен?**
Инициализация полей до тела конструктора. Обязателен для базового класса без конструктора по умолчанию, для `const`-полей и полей-ссылок.

**70. Зачем нужны геттеры и сеттеры?**
Инкапсуляция: контроль доступа и проверка значений в одном месте, возможность изменить внутреннее устройство, не трогая внешний код.

**71. Почему не `public` поля?**
Нарушается инкапсуляция: любой может записать некорректное значение.

**72. Зачем `explicit`?**
Запретить неявное преобразование типа через одноаргументный конструктор.

**73. Чем `struct` отличается от `class`?**
Только доступом по умолчанию (`public` у `struct`, `private` у `class`).

**74. Что такое `nullptr`? Почему не `NULL`?**
Типобезопасный нулевой указатель C++11. `NULL` — это `0`/`0L`, из-за чего возможна неоднозначность перегрузки.

**75. Чем ссылка отличается от указателя?**
Ссылка не бывает пустой и не переприсваивается; указатель может быть `nullptr` и менять значение.

**76. Почему в `.cpp` нет `#include <string>`?**
Он подтягивается через `student.h`. Явное включение не помешало бы, но не обязательно.

**77. Чем объявление отличается от определения?**
Объявление сообщает о существовании, определение даёт реализацию (память/код). Определение должно быть одно (ODR).

**78. Что такое компиляция и линковка?**
Компиляция переводит каждый `.cpp` в объектный файл, линковка соединяет их и сопоставляет вызовы с определениями.

**79. Почему `std::format("{:.2f}", ...)`, а не `cout << avg`?**
Фиксированный формат с двумя знаками (8.50), единообразно с лабой про транспорт.

**80. Как проверить программу на утечки?**
`g++ -fsanitize=address,undefined -g` и запуск: отчёт появится при утечке или порче памяти.

**81. Зачем отдельный заголовок и `.cpp` на каждый класс?**
Модульность и повторное использование (взять пару файлов в другой проект), меньше пересборки при изменениях, меньше конфликтов при командной работе, проще искать код.

**82. Почему `student.h` подключает `fakultet.h`, а не использует `class Fakultet;`?**
Для наследования компилятору нужен размер и состав базы, то есть полное определение. Предварительное объявление годится только для указателей и ссылок.

**83. Что будет, если забыть `#pragma once` в `fakultet.h`?**
`main.cpp` включает `student.h`, а тот `fakultet.h`; если `main.cpp` подключит ещё и `fakultet.h` напрямую, класс определится дважды: ошибка «redefinition of class Fakultet».

**84. Что будет, если забыть добавить `fakultet.cpp` в сборку?**
Компиляция пройдёт, линковка упадёт: `undefined reference to Fakultet::Fakultet(...)`, `vtable for Fakultet` и т. п.

**85. Где лучше подключать `<iostream>`: в заголовке или в `.cpp`?**
В `.cpp`, если заголовок не использует потоки в объявлениях (так у `fakultet.cpp` и `student.cpp`). Заголовок подключает только необходимое для объявлений: меньше зависимостей и быстрее компиляция. В лабе №4 `student.h` подключает `<iostream>`, потому что в объявлении `operator<<` есть `std::ostream`.

**86. В коде и раньше были виртуальные функции. Что изменилось?**
Раньше `main` держал `Student*`, и виртуальность нигде не работала: без `virtual` программа вела бы себя так же. Теперь студенты хранятся как `Fakultet*`, `input()`, `print()` и `delete` идут через базу, то есть без `virtual` программа сломается (утечка, не тот `print`).

**87. Почему `input()` чисто виртуальный, а `print()` нет?**
У `print()` в базе есть осмысленное поведение (вывод факультета), которое потомок расширяет. У `input()` для базы нет, а через указатель на базу вызывать его нужно: чисто виртуальная функция задаёт обязательный интерфейс. Класс становится абстрактным.

**88. Можно ли создать `Fakultet f("X");`?**
Нет, `Fakultet` абстрактный, компилятор выдаст ошибку. Указатели и ссылки на `Fakultet` создавать можно.

**89. Зачем `dynamic_cast` в `main`?**
`Student copy(...)` требует `Student`, а в массиве `Fakultet*`. `dynamic_cast<Student*>` безопасно приводит вниз: проверяет реальный тип во время выполнения (нужен полиморфный класс) и даёт `nullptr`, если объект не `Student`. `static_cast` быстрее, но не проверяет.

**90. Чем плох `dynamic_cast` и как его избежать?**
Он признак того, что интерфейс базы бедноват. Альтернатива: виртуальная функция `clone()` (`virtual Fakultet* clone() const = 0;`), которая возвращает копию с правильным типом без приведения.

**91. Сравните с лабой про транспорт.**
Там `Vehicle` абстрактный; `main` держит `Vehicle* object`, вызывает виртуальные `print_read_info` и `change_field`, удаляет `delete object`, а для дерева приводит `dynamic_cast<DumpTruck*>`. Мы делаем то же: `Fakultet*`, виртуальные `input`/`print`, виртуальный деструктор, `dynamic_cast`.

## 12. Шпаргалка

- Наследование: `class Derived : public Base`.
- Конструкторы: база → поля → тело. Деструкторы: наоборот.
- Параметры базе: через список инициализации.
- `virtual` + `override` = полиморфизм; `virtual ~Base()` обязателен для базовых классов.
- Класс владеет `new`-памятью → деструктор + конструктор копирования + `operator=` (правило трёх).
- Копирование глубокое; `Fakultet(other)` и `Fakultet::operator=(other)` копируют базу.
- Один метод работы с массивом (`set_results`): сначала `new`, потом `delete[]`.
- Неверный индекс → `std::out_of_range`.
- `Base::method()` отключает виртуальность.
- `Fakultet**` в `main`: нет конструктора по умолчанию у `Student` + полиморфная работа через базу (`dynamic_cast` для приведения вниз).
- Освобождение: сначала объекты, потом массив указателей.
- `std::ws` + `getline` для строк с пробелами.
- Один класс — один заголовок + один `.cpp`; `student.h` включает `fakultet.h`.
- Сборка: `g++ -std=c++20 -Wall -Wextra main.cpp fakultet.cpp student.cpp`; проверка памяти: `-fsanitize=address,undefined`.

## 13. Глоссарий

| Термин | Значение |
|---|---|
| Базовый класс | Класс, от которого наследуют (`Fakultet`) |
| Производный класс | Наследник (`Student`) |
| Инкапсуляция | Сокрытие данных, доступ через методы |
| Полиморфизм | Разное поведение по одному интерфейсу |
| Позднее связывание | Выбор функции в run-time (virtual) |
| Раннее связывание | Выбор функции при компиляции |
| vtable / vptr | Таблица виртуальных функций / указатель на неё |
| Срезка | Потеря части потомка при копировании в базу по значению |
| Глубокое копирование | Копия данных в новую память |
| RAII | Захват ресурса в конструкторе, освобождение в деструкторе |
| Утечка | Память не освобождена |
| Double free | Двойное освобождение одной памяти |
| ODR | Правило одного определения |
| Список инициализации | `: поле(значение)` после заголовка конструктора |
| Раскрутка стека | Вызов деструкторов при прохождении исключения |
| Правило трёх/пяти/нуля | Правила написания специальных функций-членов |
